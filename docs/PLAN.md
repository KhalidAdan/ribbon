# Odio build plan

Working from [NORTHSTAR.md](./NORTHSTAR.md). This is the version-one
plan: one player, one platform (Tauri on the desktop, web UI), one
library folder.

## Architecture

```
odio/
  src/core/        Pure TypeScript. No DOM, no Node, no Tauri. Culvert pipelines.
                   Everything here is unit-tested with Vitest.
  src/host/        Adapters that give core the outside world.
    host.ts        The Host interface: readDir, stat, readFile, writeFile, run(ffmpeg)
    node.ts        Node implementation. Used by tests and the `odio` CLI.
    tauri.ts       Tauri implementation over plugin-fs and plugin-shell.
  src/player/      Playback engine for the webview. Thin. Pure parts live in core.
  src/ui/          React + Tailwind 4, built with the ui.sh design skill.
  src-tauri/       Rust shell. Capabilities scoped to the chosen library folder.
  tools/           Node CLI (`npm run odio -- scan <dir>`) and fixture generator.
  test/            Vitest. Fixtures are generated by ffmpeg, never committed.
```

**Why the split.** The North Star lists ten boring things that must be
100% right. Nine of them are decisions, not pixels: how far to rewind,
which file a book offset lands in, what a position file says after two
devices disagree. Those decisions live in `src/core` as pure functions
over plain data so they can be tested exhaustively without a window,
a webview, or an audio device. The Host interface is the only seam to
the outside, and it is small enough to fake in a test.

**Culvert is the plumbing.** Library scan, loudness scan, silence scan,
and every on-disk record are Culvert pipelines. Scans are
`Source<FileEntry>` through `flatMap(probe, { concurrency })` into a
collector. Records are CSV rows through `csvStringify` into a file.
The `channel()` bridge turns ffmpeg stdout events into a pull source.

## Data model

Every durable fact is a file next to the books, in a `.odio/` folder at
the library root. All files are CSV. Nothing is binary or opaque.

| File                              | Purpose                                             |
| --------------------------------- | --------------------------------------------------- |
| `.odio/library.csv`               | One row per book. Rebuilt by scan. Cache, not truth. |
| `.odio/files.csv`                 | One row per audio file: book id, order, path, duration, size, mtime. |
| `.odio/chapters/<book>.csv`       | Effective chapters (embedded or inferred).           |
| `.odio/corrections/<book>.csv`    | Hand edits to chapters. Overlaid on top. Synced.     |
| `.odio/positions/<book>.csv`      | One row: offset_ms, updated_at, device. Synced.      |
| `.odio/loudness/<book>.csv`       | Integrated LUFS, true peak, computed gain dB.        |
| `.odio/silence/<book>.csv`        | Silence ranges per file for gap shortening.          |
| `.odio/bookmarks/<book>.csv`      | offset_ms, created_at, note, clip filename.          |
| `.odio/settings/<book>.csv`       | Per-book speed and other listener choices.           |
| `.odio/device.txt`                | This device's name. Written once.                    |

**Book id.** CRC-32 of the book's library-relative path plus total
audio byte size, rendered as eight hex characters. Stable across
devices as long as the sync engine keeps the folder layout, which is
its whole job. Moving a book breaks resume; renaming a file inside it
does not.

**Position file.** `book_id,offset_ms,updated_at,device`. One row.
Last write wins on `updated_at`, ties broken by device name so the
merge is deterministic. The sync engine moves the file; the player
only ever reads all copies it finds and writes one.

## Playback engine

The webview is WebView2, so it is Chromium: `<audio>` plays AAC in
MP4, MP3, Opus, and FLAC natively, `playbackRate` with
`preservesPitch` gives pitch-corrected speed, MediaSession gives
lock-screen and headphone keys, and Web Audio gives a gain node for
loudness. Files reach the webview through Tauri's asset protocol,
which honours HTTP range requests, so seeking never downloads a book.

**Gapless multi-file.** Two audio elements. The active one plays; the
standby one has the next file loaded and seeked to zero. On `ended`
the roles swap and the standby immediately starts, then the new
standby loads the file after that. The book timeline is one number,
milliseconds from the start of file one. `core/timeline.ts` maps
between book offset and (file index, file offset) and is tested
against off-by-one at every boundary.

**Speed.** `playbackRate` on the active element and the standby
element together. Speed is per book and persisted.

**Silence trimming.** The silence scan records every gap longer than
one second. During playback, when the position enters a recorded gap,
the engine raises the rate so the gap lasts a fixed short time, then
restores the book speed. Gaps get shorter; nothing is cut.

**Loudness.** ffmpeg's `ebur128` filter on import yields integrated
LUFS. Gain is `target - measured`, clamped to plus or minus twelve
decibels, applied through a GainNode. Target is minus eighteen LUFS.

**Resume.** On play after pause, rewind by a function of the gap:

| Away for         | Rewind                          |
| ---------------- | ------------------------------- |
| under 10 s       | 0                               |
| 10 s to 2 min    | 2 s                             |
| 2 min to 1 hour  | 10 s                            |
| 1 hour to 1 day  | 30 s                            |
| over 1 day       | 30 s and offer chapter restart  |
| over 7 days      | 60 s and offer chapter restart  |

Never rewinds past the chapter start. Never past zero.

**Sleep timer.** Modes: minutes, or end of current chapter. Fades over
the last fifteen seconds. Extending resets the fade. "Shake" becomes a
keyboard or media key on the desktop.

**Bookmarks.** A bookmark stores the offset and a note. Saving it also
runs ffmpeg to cut the previous thirty seconds into a small Opus clip
beside the bookmark row so it survives the book being moved.

## Scan pipeline

1. Walk the library folder. Emit every file with size and mtime.
2. Group into books. A folder with audio files is one book. An audio
   file with no book folder is a one-file book. Files inside a book are
   ordered by disc tag, then track tag, then natural filename sort.
3. Probe every audio file with `ffprobe -print_format json`. Extract
   duration, tags, chapters, and whether a cover stream exists.
   Concurrency four.
4. Resolve book metadata: title from album tag, author from artist or
   album_artist, narrator from composer, series and index from the
   `series` and `series-part` tags or the `mvnm` and `mvin` iTunes atoms,
   year from date. Fall back to folder name for the title.
5. Resolve cover: `cover.jpg` or `folder.jpg` in the folder, else the
   first file with an attached picture, extracted once to `.odio/covers`.
6. Build chapters. Embedded markers win. Otherwise one chapter per
   file named by the file's title tag, else the filename.
7. Overlay `corrections/<book>.csv`.
8. Write `library.csv`, `files.csv`, `chapters/<book>.csv`.
9. Queue loudness and silence scans for books without them, lowest
   priority, one at a time.

Rescans are incremental. A file whose size and mtime match `files.csv`
is not probed again.

## Order of work

Each step ends with its tests green and a commit.

1. Scaffold: Tauri 2, React, Vite, Tailwind 4, Vitest. App opens.
2. Core data: CSV records, book id, position merge. Tests.
3. Core scan: walk, group, natural sort, probe parsing, chapters,
   metadata resolution. Tests against generated fixtures and the real
   `books/` folder.
4. Node host and the `odio scan` CLI so the scan is provable without
   the app.
5. Core playback logic: timeline, resume rewind, speed and time
   remaining, sleep timer, silence policy, loudness gain. Tests.
6. Player engine in the webview: two-element gapless, gain node,
   MediaSession, position persistence.
7. Tauri host: folder picker, scoped fs, ffprobe and ffmpeg via shell.
8. UI with the ui.sh design skill: library grid, now playing, chapter
   list, sleep timer, bookmarks, chapter corrections.
9. Loudness and silence scans wired in as background jobs.
10. Bookmark clips.

Ping the user to test after step 8 at the latest, earlier if steps 6
and 7 produce something that plays.

## Deliberate omissions in version one

- No AAX. Not now, not ever, per the North Star.
- No bundled ffmpeg yet. The system binary is used. Bundling as a
  Tauri sidecar is a packaging task for after the player is right.
- No file watcher. Rescan is manual or on launch. Incremental rescan
  is cheap enough.
- No Audiobookshelf. Version two.
